parity matrix:
| area | DB31 Kani behavior | Anki parity note |
| routing | two mandatory core memories; variants share memory; repair stays inline | Kani-specific skill routing |
| lazy conversion | DB30 learning/relearning finishes in place; return to review converts in the same commit | compatibility boundary, not a third scheduler |
| learning/relearning steps | legacy steps finish unchanged; adaptive repair snapshots delays and remains practice-only | intentionally Anki-like timing where implemented |
| bury/sibling order | same-family relearning wins over review sibling; legacy mature-sibling suppression removed | session/queue suppression only, not manual unbury |
| FSRS | only real-due core checks update local Kani memory/interval; repair does not call FSRS | not Anki deck-preset or optimizer parity |
| lapses/leeches | a real-due core Fail records one lapse then routes repair/revalidation; no leech tag/suspend policy | leech-informed only for now |

boundary:
- Legacy rung, task-memory, wire, and settings state remains stored for lazy conversion and downgrade compatibility
- Adaptive variants share one of two core memories; repair state remains on the owning study_items row
- Same-session same-family hiding is the only sibling suppression layer
